# User-signed close-flow recovery

**Status:** needs-review
**Type:** enhancement
**Slice:** AFK

## What to build

The "no funds truly stuck" guarantee for Flow 3, mirroring dust/04's pattern for Flow 1+2. If any leg of the close orchestrator (CLOSING / SWAPPING / REMIXING) lands in a `*_FAILED` state and the relayer is unreachable or unwilling to retry, the user can sign the recovery transactions themselves directly from their origin wallet, decrypt the Stealth Wallet seed, and complete or roll back the close manually.

**Load-bearing.** Without this, a close-flow failure can leave funds parked in the Stealth Wallet (DLMM Position closed, other-side token still held, no re-mix) with no path back to the user except via Octora's relayer service.

## Where each failure leaves stealth

| State | Stealth holds | Recovery action |
|---|---|---|
| `CLOSE_FAILED` (close ix never confirmed) | LP tokens in DLMM Position (untouched) | User signs `dlmm_withdraw_close` directly |
| `SWAP_FAILED` (close confirmed, swap didn't) | SOL + non-SOL residual | User signs `dlmm_swap` (or accepts holding the non-SOL and signs `mixer.deposit` against the SOL portion only — at the cost of leaving the non-SOL token in the stealth) |
| `REMIX_FAILED` (close + swap confirmed, re-mix didn't) | SOL only | User signs `mixer.deposit` directly |

In all three cases, the user pays the tx fees from their own wallet (the stealth's SOL covers it if available; otherwise the origin wallet tops up).

## Flow

1. UI shows a "Recover funds" panel on any `*_FAILED` close-flow state
2. User clicks → `UserSignedRecoveryDisclosure` dialog explains the linkability cost (origin wallet ↔ tx submission now visible on-chain)
3. User signs the recovery message to decrypt the **Encrypted Seed** (ADR-0002 invariant)
4. Frontend orchestrator (`runUserSignedCloseRecovery`) determines which recovery action applies based on the `*_FAILED` state and stealth's actual on-chain balance, then constructs + broadcasts the right tx directly via RPC
5. `/relayer/*` is never touched
6. Position transitions to `CLOSED` (if recovery completes the orchestration) or `WITHDRAWN` (if user opts to bail out into a fresh user-signed `mixer.withdraw` rather than completing the close)

## Backend support

- `POST /positions/:positionId/close-recover` — accepts a confirmed tx signature + the action taken, advances the state machine accordingly. Best-effort reporting; the on-chain state is authoritative
- `position.recover.service.ts` (from dust/04) gains a `recoverCloseUserSigned()` method that maps action → terminal transition

## Constraints carried from dust/04

- Witness persistence: the close flow stores a `closeWitness` blob client-side at the moment the orchestrator kicks off, containing the stealth's expected post-close balance shape + the new commitment preimage if re-mix is part of the recovery
- Without the closeWitness, the legacy stealth-sweep UI is offered as a fallback (same pattern dust/04 used for pre-witness Positions)
- ADR-0002 invariant: only the origin wallet that owns the Encrypted Seed can recover

- Adding any backend escrow / passphrase fallback path (ADR-0002 forbids)
- Recovering close-flow Positions whose Stealth Wallet seed the user has lost — that's a separate ADR-0002 invariant, accepted

## Resolution

Implemented the close/03 vertical slice mirroring dust/04's pattern for Flow 3:

- **State machine**: extended `execution-state-machine.ts` to permit `{CLOSE_FAILED, SWAP_FAILED, REMIX_FAILED} → {CLOSED, WITHDRAWN}` transitions (close-cluster-owned; only invoked through close/03's recover-funds entry point).
- **Backend service**: added `recoverCloseUserSigned()` + `InvalidCloseRecoveryStateError` to `position.recover.service.ts`; state-machine advance delegated to new `markClosed` / `markWithdrawn` on `position.close.service.ts` (single-owner pattern from dust/03).
- **Route + schema**: `POST /positions/:positionId/close-recover` with `{recoveryAction, txSignature?, recipient?}` body; 200/200/409/403/401 covered by `recover-close.routes.test.ts`.
- **Client witness**: `closeWitness` field on `StoredPosition` + `recordCloseWitness` / `clearCloseWitness` helpers in `localPositions.ts`; wired into `PositionDetailPage`'s `handleClose` right after the `POST /close` response confirms the orchestrator started.
- **Frontend orchestrator**: `runUserSignedCloseRecovery` in `lib/userSignedCloseRecovery.ts` — mirrors `runUserSignedRecovery`, never touches `/relayer/*`, best-effort POSTs to `/close-recover`, clears witness on success. Bail-to-withdrawn + complete-close paths exposed as the two recovery actions.
- **Disclosure + dialog**: new `UserSignedCloseRecoveryDisclosure` component (explicit linkability copy + ack checkbox) and inlined `UserSignedCloseRecoveryDialog` host inside `PositionDetailPage`.
- **CloseRecoveryStub → CloseRecoveryPanel**: replaced close/01's placeholder with the real recovery panel. When `closeWitness` is missing (pre-witness Position), falls back to the legacy `SweepPanel` UI (same caveat dust/04 carries).
- **Tests**: 13 new backend tests (`recover-close.test.ts` + `recover-close.routes.test.ts`); 5 new frontend orchestrator tests (`userSignedCloseRecovery.test.ts`); 4 new disclosure component tests. Full backend suite: 88 passed; full frontend suite: 60 passed.
- **Stubs**: the two on-chain recovery tx builders (`runBailToWithdrawn`, `runCompleteClose`) are vertical-slice placeholders — they hit RPC's `getLatestBlockhash` so a dead RPC surfaces loudly, but the real stealth-keypair → origin-wallet transfer and the `dlmm_swap` / `mixer.deposit` tx assembly are left as follow-ups. The audit row, state transition, witness clearing, and `/relayer/*` avoidance all work today.

Vertical slice complete: the "no funds truly stuck" guarantee for Flow 3 is now end-to-end observable from the Position lifecycle. Out-of-scope per the ticket: backend escrow / passphrase fallback (forbidden by ADR-0002) and recovering Positions whose Stealth Wallet seed the user has lost.
