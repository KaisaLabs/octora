## What to build

Complete the tx-assembly bodies in `octora-web/src/lib/userSignedCloseRecovery.ts`:

1. **`runBailToWithdrawn`** — user-signed `mixer.withdraw` directly to a fresh recipient the user controls. Pattern: lift directly from `lib/userSignedRecovery.ts` (dust/04's analogous orchestrator for Flow 1+2). The stealth wallet's Encrypted Seed lets the origin wallet decrypt and sign, per ADR-0002. Bail-to-withdrawn means "abandon the close orchestration, mix back out, treat funds as parked".

2. **`runCompleteClose`** — depending on which `*_FAILED` state the Position is in, complete the missing leg(s) of the close orchestration under the user's signature:
   - `CLOSE_FAILED` — user signs `dlmm_withdraw_close` directly; then continues into swap (if needed) + re-mix
   - `SWAP_FAILED` — user signs `dlmm_swap` (resolving the non-SOL residual); then continues into re-mix
   - `REMIX_FAILED` — user signs `mixer.deposit` directly

   Each step requires the stealth keypair as the signer (decrypted from the Encrypted Seed). The frontend has the Stealth Wallet seed access pattern from dust/04 — reuse, don't reinvent.

3. **Slippage tolerance for the user-signed swap leg** — when `SWAP_FAILED` triggered the recovery, the user previously set a slippage tolerance via close/02's modal. Honor it: read the persisted `closeWitness` for the `expectedSwapOutLamports` value and reapply (or let the user adjust in a small follow-up dialog before signing).
