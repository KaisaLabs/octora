# Swap quote preview + slippage UI for Private Position Close

**Status:** needs-review
**Type:** enhancement
**Slice:** AFK

## What to build

Before the user confirms a close, show them the expected swap output and let them set a slippage tolerance. The close orchestrator (ticket 01) rejects the swap step if the realized output deviates beyond the user's tolerance — protecting the user from sandwich attacks, dry pools, or stale UI quotes.

Degen LP traders demand this — quote opacity is a deal-breaker for the target user (see project memory `project_target_user`).

## End-to-end flow

1. User clicks Close on an `active` Position
2. Frontend calls `GET /positions/:positionId/close-quote`
3. Backend queries Meteora DLMM for the current swap price of any non-SOL residual the stealth would hold post-close, computes:
   - Estimated stealth balances after `dlmm_withdraw_close` (SOL + other-side amounts from current bin state + accrued fees)
   - Expected SOL output of swapping the other-side residual → SOL at current price, incl. Meteora fees
   - Price impact (% deviation from spot mid)
4. UI confirmation modal shows: expected post-close SOL total, swap details (input → output, price impact, Meteora fee), denomination it will be re-mixed against, residual sub-denom dust amount that will stay in stealth
5. User picks slippage tolerance (default 0.5%, settable between 0.1% – 5%) and confirms
6. `POST /positions/:positionId/close` is called with `{ slippageBps }`; orchestrator passes the slippage cap to the `dlmm_swap` ix (`min_amount_out` parameter)
7. If realized swap output is below `min_amount_out`, the swap ix fails on-chain; close transitions to `SWAP_FAILED` and the user retries (with adjusted slippage) or recovers via ticket 03

If close-quote returns "no swap needed" (other-side residual at or below dust threshold), skip the slippage step in the UI entirely.

## API

- `GET /positions/:positionId/close-quote` — returns the structured preview above
- `POST /positions/:positionId/close` body extended with `slippageBps: number`; defaults to 50 (0.5%) if omitted; rejects values outside [10, 500]

## UI

- Confirmation modal between Close button click and orchestrator kickoff
- Slippage selector with three quick presets (0.1%, 0.5%, 1%) plus a "Custom" input
- Live recompute if user changes slippage (no network call — purely a `min_amount_out = expected * (1 - slippageBps/10000)` UI calculation)
- Display: input amount, output estimate, price impact, total post-close SOL, denomination it will re-mix against, residual dust amount
- "Confirm close" button gated until the user has either confirmed default slippage or set a custom value

### Notes

- The dust-threshold swap-skip rule is shared between the quote service and the orchestrator via `CLOSE_SWAP_DUST_THRESHOLD_LAMPORTS` — single source of truth, so the UI never previews a swap step the orchestrator would skip and vice versa.
- The `closeQuote` route is intentionally public (no wallet auth) to mirror `GET /positions/:id`; the close-quote endpoint is symmetric to that read. The mutating `POST /close` stays wallet-gated.
- `CloseConfirmDialog` is pure-props (no router, no fetch) so it's directly unit-testable without mounting a memory router or stubbing fetch.
