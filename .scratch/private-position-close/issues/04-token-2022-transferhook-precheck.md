# Token-2022 / TransferHook precheck for close

**Status:** needs-review
**Type:** enhancement
**Slice:** AFK

## What to build

Block Private Position Close from initiating when the DLMM pool's non-SOL side is a mint the current Executor cannot handle. Per project memory `project_executor_v2_upgrade`: plain Token-2022 works; mints with the **TransferHook** extension are still gated for v2. A close attempt against a TransferHook'd mint would fail mid-orchestration (probably at `SWAPPING`) and leave the user in a `SWAP_FAILED` recovery state for no good reason — better to refuse the close upfront with an honest message.

This applies *only* if the other-side token is non-SOL and the close-quote (ticket 02) shows a swap will actually run. Pools where the close produces only SOL (no swap step) skip this check.

## Detection

Read the mint account for the non-SOL side. Check the extension list for `TransferHook` (or any other Executor-blocked extension — list lives in `programs/octora-executor/src/cpi/` or equivalent). The exact set of blocked extensions should be sourced from the Executor's known-good list, not duplicated here — if the Executor adds support for an extension in the future, this precheck should pick that up without a new release.

## Backend

- New helper: `assertExecutorSupportsMint(mint: PublicKey): Promise<void>` that reads the mint account and throws `UnsupportedMintExtensionError` (extending `ValidationError`, HTTP 422, stable code `unsupported_mint_extension`) if any blocked extension is present
- Wire into `close-quote` (ticket 02): if the swap step is needed and the mint check fails, return `{ closeable: false, reason: "unsupported_mint", details: { mint, extension: "TransferHook" } }` instead of a quote
- Wire into `POST /positions/:positionId/close`: refuse upfront with the same error

## UI

- Close button disabled when the Position's pool has a TransferHook'd (or otherwise unsupported) non-SOL mint
- Tooltip on the disabled button explains: "Close is not yet available for pools that include {extension} mints. This is a v2 capability."
- Position list row: visual indicator (e.g. badge or dimmed appearance) on positions that are presently un-closeable, so users can see at a glance

- Pre-flight checks for the SOL side (always native SOL in MVP scope, no precheck needed)
- Other extension types not currently in the blocked list — they'll be auto-detected once added to the Executor's source-of-truth list
