# Wire production executor + mixer ix into close adapters

**Status:** ready-for-agent
**Type:** enhancement
**Slice:** AFK

## What to build

Flow 3 (Private Position Close) ships with three adapter interfaces, all currently shipping with scope-down placeholders. This ticket replaces the placeholders with production wiring to the live Executor + Mixer clients. No new state machine work; no new endpoints; no new UI. Just plug real ix builders into the existing contracts.

**Three places that share the same gap:**

1. **`CloseOrchestrationAdapter`** (close/01) — `position.close.service.ts`. Methods: `submitWithdrawClose`, `submitSwap`, `submitRemix`. Production deployments don't pass `closeAdapter` today; production wiring connects the relayer-signed close orchestrator end-to-end.

2. **`CloseQuoteAdapter`** (close/02) — `position.close-quote.service.ts`. Method: `computeSwapOut(otherSideLamports, mintA, mintB)` returns expected swap output + price impact. Production wiring delegates to the existing `getSwapQuote` in `dlmm.chain.ts`.

3. **`buildCloseRecoveryTx`** (close/06) — `position.close-builder.service.ts`. Per-leg builders for `withdraw-close` / `swap` / `mixer-deposit`. Currently emits zero-lamport `SystemProgram.transfer` placeholders. Production wiring builds real ixs via `OctoraExecutorClient.buildWithdrawCloseIx` / `buildSwapIx` + `mixer.service.ts` deposit-ix builder.

**Common dependencies all three need:**

- `OctoraExecutorClient.buildSwapIx` is currently **missing** from the executor client (per close/01 worker's scope-down note). The Rust ix exists in `programs/octora-executor/src/instructions/dlmm/swap.rs` (or wherever DLMM swap lives — verify). Add the TS-side builder method first.
- `mixer.service.ts` already has the deposit-tx builder used elsewhere — reuse, don't reinvent.
- `dlmm.chain.ts` `getSwapQuote` already exists per close/01 worker's notes — reuse.

## End-to-end flow once landed

- A user clicks Close on an `active` Position → close/02's modal opens with a **real** swap quote + price impact from the live pool
- User confirms slippage → backend orchestrator submits **real** `dlmm_withdraw_close` → conditional **real** `dlmm_swap` (with the user's `min_amount_out` cap) → **real** `mixer.deposit` for a fresh Commitment
- If any leg fails and the user invokes close-recovery → the close-builder route hands back **real** unsigned txs that the stealth keypair signs
