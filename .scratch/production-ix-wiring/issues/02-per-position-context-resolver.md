# Per-position context resolver + relayer signer seam

**Status:** ready-for-agent
**Type:** enhancement
**Slice:** AFK

## What to build

production-ix-wiring/01 landed the production close adapters end-to-end as plumbing, but every adapter method that needs per-position chain context throws `*WiringIncompleteError` (503) until a resolver lands. This ticket closes the gap.

**Three things to land:**

1. **Per-position context resolver** — persisted or computed-on-demand chain context for every `active` Position, exposing:
   - `stealthPubkey: PublicKey` + a way to retrieve the relayer-side stealth keypair (the backend signs as the stealth in the relayer-driven close orchestrator; the user-signed recovery path derives the stealth client-side from the Encrypted Seed and is unaffected by this resolver)
   - `lbPair: PublicKey` — Meteora DLMM pool address
   - `positionPubkey: PublicKey` — the Meteora DLMM Position account
   - `binRange: { lowerBinId: i32, upperBinId: i32 }` — for the withdraw-close + swap legs
   - `dlmmRemainingAccounts: AccountMeta[]` — the bin-array + reserve + token-program accounts the DLMM ix needs
   - `ataPubkeys: { stealthSolAta?, stealthOtherAta?, ... }` — the stealth's ATAs for the pool's two token sides
   - `denominationLamports: bigint` — the Mixer Pool denomination this Position deposited against (matches close/05's caveat — currently hard-coded client-side; persist server-side now)
   - `nextCommitmentPreimage` / similar — the inputs the `submitMixerDeposit` leg needs to mint a fresh Commitment for the re-mix

   Implementation choice: either widen `PositionRow` with these columns (Prisma migration) OR ship a `CloseContextResolver` service that reads chain state on demand (slower but no schema change). The worker should pick whichever produces the right cost/complexity trade-off — both are valid; document the decision in the resolution comment.

2. **Relayer signer seam** — `submitMixerDeposit` in the production close adapter currently builds the unsigned tx and then throws `CloseOrchestrationWiringIncompleteError`. Wire the relayer's signer (same path the existing `mixer.deposit` flow uses for ordinary Flow 1 deposits) so the orchestrator can actually submit. The relayer's signing capability already exists elsewhere — find the call site and reuse.

3. **ATA-read for `otherSideResidualLamports`** — the production close-quote adapter and the orchestrator both currently see `0n` for the stealth's other-side residual. Once the resolver exposes `stealthOtherAta`, read the live balance (RPC) and surface it. The orchestrator's existing swap-skip-on-dust-threshold logic then works end-to-end without further changes.

## End-to-end demoable

Once landed, a fully wired production deployment can:

- Quote a close (real `dlmm.chain.getSwapQuote` + real stealth ATA reads)
- Submit a relayer-signed close → real `dlmm_withdraw_close` → conditional `dlmm_swap` with real `min_amount_out` → real `mixer.deposit` → CLOSED
- Recover via the user-signed flow (already complete — close/06 landed) using the same per-position context for the close-builder legs
