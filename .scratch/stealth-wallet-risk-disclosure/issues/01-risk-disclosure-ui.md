# Stealth Wallet origin-wallet-only risk disclosure UI

**Status:** ready-for-agent
**Type:** enhancement
**Slice:** AFK

## What to build

Surface the invariant from **ADR-0002** (`octora-api/docs/adr/0002-stealth-wallet-recovery-requires-origin-wallet.md`) in the UI so users understand it *before* they create a Position.

The invariant: a Stealth Wallet's Encrypted Seed can only be decrypted by the origin wallet that produced its `signMessage()`. There is no backend escrow, no passphrase fallback. **Lose the origin wallet → permanently lose the funds inside that Position's DLMM Position.**

Where to disclose:

1. **Strategy Setup** — a checkbox or persistent callout before the user can submit. Copy must say "lose wallet = lose funds" explicitly, not euphemistically.
2. **PrivateDepositModal** — same warning on the final confirmation step before signing.
3. **Onboarding** (if it exists, or wire to first-Position creation) — once-per-user explanation of the trade-off.

Copy guidance:

- Plain English, not legalese
- Name the consequence concretely ("the SOL in this position will be unrecoverable")
- Avoid words like "complex" / "advanced" — the user is a degen LP trader, treat them as informed
- Privacy is *why* this is the case — say so. The disclosure is also a feature pitch.

## Acceptance criteria

- [ ] Strategy Setup has a visible risk callout that the user must acknowledge before submitting
- [ ] PrivateDepositModal final-confirm step shows the same warning
- [ ] Copy explicitly says "lose origin wallet = lose Position funds" (or equivalent direct phrasing)
- [ ] Disclosure references *why* this design exists (privacy / unlinkability) in one sentence
- [ ] Accessibility: warning is announced by screen readers, not just visually styled
- [ ] No backend recovery affordance is added — confirm by code review that no escrow/passphrase path slipped in

None — can start immediately.
