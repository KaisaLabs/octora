# "Recover funds" user-signed withdraw fallback

**Status:** ready-for-agent
**Type:** enhancement
**Slice:** AFK

## What to build

A user-signed escape hatch for the edge case where the relayer disappears mid-flow. The user can always recover their own funds without depending on Octora's backend.

Flow:

- UI surfaces a **"Recover funds"** button on any Position in `LP_FAILED` or `PARKED` state
- Clicking it constructs a user-signed `mixer.withdraw` directly to a fresh stealth they control, paying the relayer fee themselves
- Requires the user to hold the nullifier preimage (which they always do — see ADR-0002 / Stealth Wallet recovery invariant)
- Treat as the worst-case-but-always-available SAFE path. Never gated on backend availability.

Privacy note: a user-signed recover *does* link the origin wallet to the withdraw destination on-chain. The UI must disclose this trade-off explicitly — same disclosure pattern as Mode Fallback (ADR-0001).

## Acceptance criteria

- [ ] "Recover funds" button appears in `LP_FAILED` and `PARKED` UI panels
- [ ] Clicking it builds and broadcasts a user-signed `mixer.withdraw` without backend signing
- [ ] Works against a stopped relayer (test by killing the relayer service before clicking)
- [ ] UI disclosure explains the privacy trade-off (origin wallet → withdraw destination becomes linkable)
- [ ] Recovered Position transitions to `WITHDRAWN` (terminal)
- [ ] Integration test exercises the path end-to-end with the relayer offline
