# Denomination ladder: {0.1, 1, 5, 10} SOL

**Status:** needs-review
**Type:** enhancement
**Slice:** AFK

## What to build

Extend the Mixer Pool denomination tiers from the current MVP (which ships a single tier or two) to a ladder of `{0.1, 1, 5, 10}` SOL. Smaller buckets produce less residual dust after a DLMM price-range fit; the trade-off is that more buckets fragment the anonymity set, so the ladder must be paired with strict per-bucket anonymity guarding.

End-to-end:

- On-chain: initialize a Mixer Pool PDA for each new denomination (`mixer_pool_seed + denom.to_le_bytes()`)
- Backend: `mixer.service.ts` supports multi-denom routing (already partial — see Day 1 memory). Verify each denom has its own Anonymity Set Guard with `MIN_ANONYMITY_SET = 20`.
- UI: `Denomination Picker` shows the ladder. **Hide buckets that have not yet reached `MIN_ANONYMITY_SET` from the picker entirely** — never present a denom the backend will refuse. (See feedback memory: prefer disabled-with-explanation over fictional inputs.)

## Acceptance criteria

- [ ] On-chain `Initialize` ix runs for each of `{0.1, 1, 5, 10}` SOL on devnet + mainnet (mainnet deploy is a separate manual step — issue tracks readiness, not the deploy itself)
- [ ] Backend exposes the list of currently-active denoms via API
- [ ] Anonymity Set Guard enforces `MIN_ANONYMITY_SET = 20` independently per denom
- [ ] Denomination Picker hides buckets below threshold; tooltip on disabled UI element (if any) explains *why*
- [ ] Integration test: depositing to an empty 0.1 SOL pool, then trying to withdraw from it, fails with the `AnonymitySetTooThinError`
- [ ] Existing single-denom Position flow still works (no regression on the 1 SOL tier)

   bootstrap produces all four Mixer Pool PDAs in one run. No on-chain

   per denom.
