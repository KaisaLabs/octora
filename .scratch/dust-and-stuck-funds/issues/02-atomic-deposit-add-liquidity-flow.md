# Atomic deposit+addLP user flow

**Status:** wontfix
**Type:** enhancement
**Slice:** AFK

## What to build

Ship the single-tx **Private Deposit + Position Open** flow:

```
user.sign:
  mixer.deposit (commitment)
  CPI -> pool.add_liquidity (via relayer-derived stealth or PDA)
```

End-to-end: user picks a denomination and a DLMM pool in **Strategy Setup**, signs one transaction, and the resulting **DLMM Position** is owned by their **Stealth Wallet**. If the `add_liquidity` leg fails, the whole tx reverts and SOL never leaves the user's wallet — by construction, the **stuck-funds** state for this flow ceases to exist.

Ship this only if the prototype (issue 01) confirmed CU + tx-size fit. If not, this ticket converts into a tracking ticket for the constraint that blocked it, and the two-phase ticket (03) becomes the primary path.

## Acceptance criteria

- [ ] Single user signature opens a new Position end-to-end on surfpool against a representative DLMM pool
- [ ] On simulated `add_liquidity` failure, the whole tx reverts and user wallet shows no balance change
- [ ] `Position` state machine moves directly from `awaiting_signature` to `indexing` (no transient `funding-partial` Failure Stage possible on this path)
- [ ] Integration test covers the success path and the simulated-revert path
- [ ] UI shows one progress indicator, not separate "depositing" + "adding liquidity" phases

### Closure — 2026-05-15 (wontfix per ADR-0004)

> *This was generated by AI during triage.*

User-signed atomic deposit+addLP is infeasible at current account-encoding density: measured tx-size = 1268 bytes, exceeds Solana's 1232-byte packet limit by 36 bytes. CU budget is not the constraint.

See ADR-0004 (`octora-api/docs/adr/0004-atomic-deposit-add-liquidity-blocked-by-tx-size.md`) for measurements, mitigations considered (LUT, prep-tx split, account compression), and the consequence: dust/03 (two-phase deposit→LP state machine) is promoted from defense-in-depth to the primary path.

Reopen when an LUT-based version of the atomic tx is built — the LUT alone recovers >150 bytes, well over the 36-byte deficit. That work would supersede ADR-0004 with a new design + re-measurement.

Closing as wontfix at current density.
