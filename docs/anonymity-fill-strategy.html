Octora — Anonymity Set Fill Strategy

How to bootstrap and sustain the mixer's anonymity set on mainnet, and how to test the strategy on localnet first.

1. Why this matters

The mixer's privacy guarantee is bounded by the anonymity set — the count of deposits in a given denomination pool that could have funded any one withdrawal.

From runbooks/PRIVACY_MODEL.md §4:

Anonymity set sizeLinkability per withdrawal
< 10Near-trivial. Amount + timing pinpoints the deposit.
10–50Weak. Chainalysis-class tooling typically recovers it.
50–500Moderate. Effective vs. non-state adversaries.
500+Strong. Comparable to Tornado Cash classic at peak.

Hard floor: MIN_ANONYMITY_SET = 20 per pool. The relayer should refuse a withdraw below this (P1-18, gate on roadmap).

2. Levers we control

Primary: seed liquidity

  • Many fresh wallets, not one wallet × N times. Same-wallet deposits cluster — observer infers they belong to one operator.
  • Concentrate, don't fragment. Launch with 2–3 denoms (e.g. 0.1, 1, 10 SOL); open higher tiers only after demand exists. Per docs/POOL_ROTATION.md, the supported denom ladder is {0.1, 1, 5, 10} SOL.
  • Each denom must hit ≥ 20 deposits before the first withdrawal lands. Otherwise the first withdrawer is the deanonymization case study.
  • Stagger over hours/days with randomized intervals. Bursts at round-number times leak.

Secondary: protocol gates

  • Privacy delay — OCTORA_MIXER_PRIVACY_DELAY_MS (default 13s). Consider raising to 60–120s for the first weeks of mainnet.
  • Min-N gate (P1-18) — relayer must refuse withdrawals when set_size < MIN_ANONYMITY_SET. Ship before mainnet open. Without this, a single first-withdrawer is fully linkable.
  • Per-denom withdrawal rate limit — withdrawals per minute capped so set drain < deposit rate. Prevents an attacker draining the set to trivialize subsequent withdraws.

Tertiary: incentives

  • Fee rebate / points multiplier scaling with time-in-pool. Withdraw fast → forfeit rebate. Aligns user incentive with anonymity-set health.
  • Cohort launches. Announce deposit windows ("Tuesday 14:00 UTC"). Each depositor inherits the cohort's anonymity set for free.
  • Surface set size in UI. /vault/info already exposes anonymitySetSize; show RED <10, YELLOW 10–50, GREEN 50+. Lets self-policing users delay.

3. Mainnet playbook (T-7d → T+30d)

T-7d: gate work

  • Implement P1-18 min-N gate in octora-api/src/modules/relayer/relayer.service.ts.
  • Set OCTORA_MIXER_PRIVACY_DELAY_MS=60000 for first 30 days.
  • Set BETA_MAX_* caps to limit any single user's contribution to ≤ 10% of pool deposits.
  • Add Grafana panel for per-denom anonymitySetSize; alert when < 20.

T-1d: dry run on devnet

  • Run the localnet fill script (§5) against devnet with NETWORK=devnet. Verify witness JSON is recoverable end-to-end before risking mainnet SOL.

T-0: seeded launch

  • Seed each active denom from ≥ 30 fresh wallets over 2–4 hours with randomized inter-deposit intervals (60–600s).
  • Keep withdrawals paused (or denom-list empty in /relayer/info) until set_size ≥ 30 per denom.
  • Persist every (secret, nullifier, commitment, leafIndex, denomination) tuple to an offline-signed witness file. Without it, your seed SOL is permanently locked.

T+1d → T+30d: sustain

  • Top up any denom that drops < 25.
  • Run a small "background depositor" service that adds 1 deposit / hour at randomized intervals to thin pools, capped by a daily budget.
  • Roll forward seed-wallet rotation: never reuse a seed wallet within 30 days.
Anti-patterns to avoid
  • One ops wallet depositing 20× to "fill the set". Linkable on the depositor side; the entire seed cohort collapses to one entity.
  • Withdrawing your own seed deposits early. Pool drains, real users are now in a thin set.
  • Skipping witness persistence. If you lose the secret/nullifier, the seed SOL is unrecoverable. scripts/anon-fill-localnet.ts writes a JSON file — never delete it.
  • Bursty deposits. 30 deposits at exactly 00:00:00, 00:01:00, 00:02:00 is a fingerprint.

4. Recovery story (do not skip)

Every seed deposit is recoverable if and only if you keep its commitment witness — (secret, nullifier, commitment, leafIndex, denomination). Lose the file → SOL stays in the pool forever.

The localnet script writes scripts/.anon-fill-witnesses.json. For mainnet:

  • Encrypt the witness file at rest (e.g. age or gpg --symmetric).
  • Back up to a secondary location before running the next batch.
  • Test recovery on devnet first by running a withdrawal from a recorded witness via the standard Groth16 prove + relayer flow.

5. Localnet fill — how to run it

Prereqs

  1. Programs deployed to localnet — NETWORK=localnet ./scripts/localnet-bootstrap.sh
  2. Mixer pools initialized — pnpm tsx scripts/init-mixer-pools.ts (writes pools for the four default denominations).
  3. Funder keypair has enough SOL — for 30 deposits × 0.1 SOL denom, budget ≥ 5 SOL to cover deposit + rent + fees per fresh wallet.

Run

# default: 30 deposits per denom, denominations from MIXER_DENOMINATIONS env
OCTORA_MIXER_PROGRAM_ID=<your_program_id> \
OCTORA_MIXER_ADMIN_KEYPAIR=$HOME/.config/solana/id.json \
OCTORA_EXECUTOR_RPC_URL=http://127.0.0.1:8899 \
pnpm tsx scripts/anon-fill-localnet.ts

# tune:
ANON_FILL_PER_DENOM=50 \              # deposits per denom
ANON_FILL_DENOMS=100000000,1000000000 \   # subset of denoms (lamports)
ANON_FILL_MIN_DELAY_MS=200 \           # min inter-deposit pause
ANON_FILL_MAX_DELAY_MS=2000 \          # max inter-deposit pause
ANON_FILL_WITNESS_FILE=./scripts/.anon-fill-witnesses.json \
pnpm tsx scripts/anon-fill-localnet.ts

What it does

  1. Loads the funder keypair (your admin / dev wallet).
  2. For each denom × ANON_FILL_PER_DENOM iterations:
    • Generates a fresh Keypair (one-time-use depositor).
    • Funds it from the admin with denom + rent + fees.
    • Generates a Poseidon commitment from random (secret, nullifier).
    • Submits mixer.deposit from the fresh wallet.
    • Appends the witness tuple to the JSON file (atomic-write per row — so a kill mid-run doesn't lose prior work).
    • Sleeps uniform(MIN_DELAY, MAX_DELAY) ms.
  3. Prints final per-denom nextLeafIndex so you can verify the set grew as expected.

Verify

# per-pool count via API
curl http://localhost:3000/api/mixer/status?denomination=1000000000

# or direct on-chain — read MixerPool.next_leaf_index for the PDA
solana account <mixer_pool_pda> --url http://127.0.0.1:8899

6. Mainnet variant — what changes

  1. Use a hardware-wallet-derived funder (or multisig). Never use a hot key for the seed budget.
  2. Set OCTORA_EXECUTOR_RPC_URL=https://api.mainnet-beta.solana.com (or your private RPC).
  3. Encrypt the witness file the moment the script exits: age -p -o witnesses.age scripts/.anon-fill-witnesses.json && shred -u scripts/.anon-fill-witnesses.json.
  4. Run from a single source IP — observers correlating IPs is out of scope, but rotating IPs adds nothing for anonymity-set growth.
  5. Cap per-run iterations at 5–10 deposits then re-run after a randomized cool-off; one giant batch is bursty.

7. Open questions / gaps

  • P1-18 min-N gate is not yet implemented. Until shipped, "first withdrawer is fully linkable" remains the worst-case.
  • No automatic background depositor. Today the fill is operator-triggered. A scheduled task running the script with budget caps would be cleaner — tracked separately.
  • Withdrawal rate limit not enforced. Set drain can outpace seed rate during volume spikes.
  • UI doesn't yet color-code anonymitySetSize. Backend exposes it; frontend treatment is a small follow-up.
