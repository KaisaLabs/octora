Octora — Trace Linkage & Verify Bot Resistance

Trace main wallet → mixer → stealth → pool on Solana explorers. Verify copy-trader bots cannot follow.

Tools

  • Solscan — best for token flow + multi-tx view
  • Solana Explorer — official, raw ix data
  • SolanaFM — graph view + account labelling
  • solana-cli — scriptable verification

Step-by-step trace

1. Main wallet → mixer deposit

  • Open main wallet on Solscan → tab Transactions / SOL Transfers
  • Find deposit tx to mixer program. Note:
    • signer = main wallet
    • instruction calls mixer program ID
    • SOL amount = denom bucket (e.g. 1, 5, 10 SOL)
  • Copy tx signature. Confirm mixer PDA receives lamports.

2. Mixer commitment

In tx Instruction Details, find commitment (32-byte hash) logged. = nullifier preimage anchor. Public but unlinkable to withdrawal.

3. Mixer withdraw → stealth address

  • Search mixer program ID → filter withdraw ix
  • Find withdraw tx where recipient = stealth pubkey. Signer = relayer (or fresh wallet, not main).
  • Key check: no ix-level link main_wallet ↔ stealth. Only shared mixer program + denom.

4. Stealth → pool deposit

  • Open stealth address. Tx list → deposit ix into pool (e.g. DLMM addLiquidity, position open)
  • Signer = stealth. Funding source = mixer withdraw tx.

Linkage attack surface

What copy-bot scans for, and Octora's defense:

HeuristicDefense
Same signer across deposit + poolstealth ≠ main, separate keys
Exact-amount match (deposit = pool size)Fixed denom buckets + change handling
Timing correlation (deposit + withdraw within Xs)Relayer delay / batching
Anonymity-set-of-1 (only one deposit of that denom in window)MIN_ANONYMITY_SET=20 gate
Fee-payer = main walletRelayer pays fees, not user
Shared rent-payer / referrer fieldScrub, use stealth

Verify "hard to copy"

Run these probes on mainnet / surfpool:

A. Graph-trace probe

solscan main_wallet -> list all outgoing tx
  for each tx: follow recipient 2 hops
  assert: stealth NOT reachable via direct SOL path

Use solana-cli + getSignaturesForAddress → walk graph. If main→stealth path exists outside mixer program = LEAK

B. Co-spend / common-input heuristic

  • Check no tx ever uses both main_wallet and stealth as signers/writable accounts. Single co-spend = full deanon.
solana confirm <sig> --output json \
  | jq '.transaction.message.accountKeys'

For every stealth tx. Grep for main pubkey.

C. Amount-fingerprint probe

  • Mixer denom must be common bucket. Deposit 7.3 SOL → pool position 7.3 SOL = trivial fingerprint.
  • Verify: pool deposit ∈ {denom, denom-fee, denom-rent}. No custom fractional leak.

D. Timing probe

  • Δt(deposit, withdraw) distribution must overlap with other users in same denom bucket.
  • If your withdraw always = deposit + 30s = unique signature in time-amount space → LEAK

E. Anonymity-set size

  • Query mixer commitments at withdraw time. Count = N.
  • MIN_ANONYMITY_SET=20 → bot has ≤1/20 = 5% guess.
  • Below 20 = withdraw rejects.

F. Bot simulation

Write naive copy-bot:

# pseudo
for tx in watch(main_wallet):
    if is_pool_deposit(tx):
        copy(tx)
  • Run against mainnet beta.
  • Bot copies your pool entry → LEAK
  • Bot sees nothing after mixer → PASS

G. Fee-payer audit

tx.message.accountKeys[0] = fee payer. Across full flow:

  • deposit: main_wallet OK (public)
  • withdraw: relayer OK (NOT main)
  • pool: stealth or relayer OK (NOT main)
  • Any main_wallet as fee payer post-mix = LEAK

Quick CLI verify

# all sigs for stealth
solana transaction-history <STEALTH> --limit 50

# for each sig, dump signers + writable accounts
solana confirm -v <SIG> | grep -E "Signer|Writable"

# grep for main wallet pubkey -> must be empty

Grep empty across full stealth history → on-chain unlinkable. Bot must rely on off-chain (IP, timing, behavioral) = out of scope.

Bottom line — on-chain unlinkability checklist

  1. No shared signer
  2. No shared fee payer
  3. No exact-amount leak
  4. Anonymity set ≥ 20 at withdraw
  5. No graph path main → stealth outside mixer program

Verify all 5 per flow → bot blind on-chain.
